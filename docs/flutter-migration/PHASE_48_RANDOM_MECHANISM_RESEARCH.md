# Phase 48：Random Feed Research and Hardening

## 公开协议结论

检索公开 JHenTai/EhViewer/TaroEH 实现后，没有发现可稳定依赖的独立随机 API。现有客户端通常从站点可访问首页/游标页面抽取，再在客户端随机选择；不能把 `artist:random` 当作随机 API。

## 当前增强

- 随机批次从 12 提升到 18。
- 单批次随机游标探测从 8 提升到最多 16。
- 每批次维护独立 cursor set，避免重复探测。
- 当前随机会话通过全量已有 GalleryKey/gid 排除重复。
- 无新结果时 `randomExhausted` 结束会话，避免无限撞站。
- 随机按钮“换一批”创建新会话；下拉刷新也创建新会话。
- 随机列表结果末尾只在 `hasMore` 时显示继续加载项。
- UI 显示随机轮次和已发现数量。

## 站点限制

随机结果质量受站点游标、访问权限、ghost/限制页和当前可探测 gid 范围影响。系统保证“不重复、可继续、失败可重试”，但不宣称无限唯一结果或实时随机 API。
